# OBD Tool — Android OBD2 Bluetooth App (Kotlin)

اپلیکیشن پایه برای اتصال به دانگل بلوتوثی OBD2 (سازگار با ELM327)، خواندن داده‌های
زنده موتور، خواندن/پاک‌کردن کدهای خطا (DTC)، و اجرای تست عملگر از طریق UDS.

## ساختار پروژه

```
app/src/main/java/com/example/obdtool/
├── bluetooth/
│   └── BluetoothObdManager.kt   # اتصال Classic Bluetooth (SPP) و ارسال/دریافت دستورات AT/OBD
├── obd/
│   ├── ObdPids.kt                # تعریف PID های استاندارد Mode 01 و پارس پاسخ‌ها
│   ├── DtcReader.kt               # خواندن (Mode 03) و پاک‌کردن (Mode 04) کدهای خطا
│   └── ActuatorTester.kt          # فریم‌ورک تست عملگر روی UDS Routine Control (0x31)
└── ui/
    ├── ObdViewModel.kt
    ├── ConnectScreen.kt
    └── DataScreens.kt             # صفحات داده زنده، DTC، عملگرها
```

## قبل از اجرا

1. دانگل ELM327 را از تنظیمات بلوتوث گوشی جفت (pair) کن (پین معمولاً `1234` یا `0000`).
2. پروژه را در Android Studio (Hedgehog یا جدیدتر) باز کن و Sync بگیر.
3. روی گوشی نصب و اجرا کن؛ در اولین اجرا مجوز بلوتوث را بده.
4. از تب «اتصال»، دانگل جفت‌شده را انتخاب کن.

## چه چیزی همین الان کار می‌کند

- اتصال به دانگل و مقداردهی اولیه چیپ ELM327
- خواندن زنده RPM، سرعت، دما، بار موتور، موقعیت گاز، آوانس جرقه فعلی (فقط خواندن)
- خواندن و پاک‌کردن DTC ها (استاندارد و قابل اعتماد روی همه خودروهای OBD2)
- زیرساخت تست عملگر (شروع/توقف/گرفتن نتیجه روتین UDS)

## محدودیت مهم: تغییر پارامترهای سوخت/جرقه/دما

این بخش **عمداً پیاده‌سازی نشده** چون فنی و قانونی محدودیت‌های واقعی داره، نه اینکه یک
قابلیت جاافتاده باشه:

- استاندارد OBD2 (SAE J1979) اصلاً سرویس «نوشتن» برای این پارامترها ندارد؛ فقط خواندن.
- تغییر واقعی نقشه سوخت/جرقه از طریق UDS Security Access (سرویس 0x27) انجام می‌شه که
  الگوریتم seed/key آن مختص هر ECU/نرم‌افزار است و عمومی منتشر نمی‌شود.
- آدرس‌دهی حافظه و ساختار جدول‌ها هم مخصوص هر ECU است — این اطلاعات معمولاً از طریق
  فایل‌های کالیبراسیون تجاری (HP Tuners، EFI Live، Cobb، ETAS INCA و...) یا مهندسی
  معکوس به‌دست میاد، نه از یک اپ عمومی.
- در بسیاری کشورها (مثلاً طبق قوانین EPA در آمریکا) تغییر پارامترهای مرتبط با آلایندگی
  روی خودروی دارای پلاک، از نظر قانونی محدود است.

اگر برای یک خودروی مشخص، شناسه‌های روتین UDS یا مستندات کالیبراسیون را در اختیار داری،
همان الگوی `ActuatorTester.kt` (ارسال دستور خام از طریق `BluetoothObdManager.sendRawCommand()`)
را می‌شه برای آن پیاده‌سازی کرد.

## قدم بعدی پیشنهادی

برای «تست عملگر»، لیست `knownRoutines` در `ActuatorTester.kt` را با شناسه‌های واقعی
مستندشده برای خودروی خودت پر کن؛ در حال حاضر خالی است چون این شناسه‌ها بین برندها و
حتی بین سال‌های تولید یک مدل هم فرق می‌کنند.
